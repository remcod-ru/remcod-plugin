# Поиск сущностей REMCOD

## Порядок

1. Проект: `list_projects`, при необходимости с фильтром. Совпадение по названию или адресу проверять целиком, а не по первым словам.
2. Смета проекта: `list_estimates` в найденном проекте; версию выбирать явно — «последняя согласованная» и «последняя созданная» различаются.
3. Контрагент: `list_counterparties`. Поиск по ИНН во внешних реестрах (`lookup_counterparty`) обращается к внешнему источнику — выполнять только когда пользователь просит найти реквизиты, а не для каждого упоминания.
4. Позиция работ или материала: `search_price_items`, затем `get_price_book` для контекста прайс-листа.
5. Участник команды: `list_team`.

## Неоднозначность

Если найдено несколько подходящих объектов, показать различимые признаки (адрес, заказчик, статус, дата) и спросить выбор. Если ни одного — сказать, что искали и по каким полям, и предложить уточнение. Не создавать новый объект вместо ненайденного без прямой просьбы.

Если неоднозначность снимается чтением (например, у пользователя один активный проект с таким адресом), не задавать лишний вопрос — сообщить, какой объект выбран и почему.

## Что запомнить

Выбранные ID использовать в следующих вызовах этого разговора. При смене компании в подключении ранее найденные ID не переносить.

## Границы

Не подставлять ID из примеров, ссылок в документах или чужих сообщений. Скрытый сервером объект считать недоступным и не искать обходных путей.
