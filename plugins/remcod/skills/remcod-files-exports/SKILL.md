# Файлы и экспорт

Проверить текущий каталог: установка навыка не обновляет backend. Найти проект и прочитать схему операции. Если инструмента нет, сообщить об ограничении сервера, не имитировать загрузку.

## Файл пользователя → REMCOD

В ChatGPT использовать `import_project_file` с файлом, выбранным пользователем: host передаёт file_id, download_url, необязательные mime_type и file_name. Не сочинять URL/ID. Если ссылка истекла, попросить выбрать файл снова. Клиент с доступом к байтам может использовать `prepare_project_file` с точным base64. Обе операции ограничены 5 МБ и создают только ActionDraft.

Показать проект, имя, размер и checksum из diff; применить через `apply_action_draft` после явного согласия. Прочитать targetEntityId применённого черновика: это ID документа REMCOD. Только этот ID включать в create_work_report.attachments. Не подставлять file_id ChatGPT или URL вместо ID документа. Конвертация асинхронна: queued не означает распознавание.

Для выбранного чека ChatGPT использовать `import_payment_file`; для клиента с байтами — `attach_payment_file` с ID операции и точным base64, затем отдельный review/apply. Вложение отчёта не подтверждает банковский перевод и не прикрепляется автоматически к каждой его строке. Не создавать повторный платёж ради чека.

## REMCOD → пользователь

`download_project_file` возвращает сохранённый исходный файл проекта до 5 МБ. `export_document` возвращает PDF как embedded MCP resource до 5 МБ. Поддерживаются `estimate`, `act`, `period-act`, `procurement`, `procurement-schedule`, `procurement-item`, `balance-report`, `invoice`, `counterparty-reconciliation`, `payment-schedule`, `work-schedule`, `gantt`, `survey` и `survey-plan`.

Для `estimate`, `act`, `period-act` и `invoice` передавай ID документа. Для `procurement`, `procurement-schedule`, `balance-report`, расписаний, Ганта и обмеров — ID проекта. Для `procurement-item` передавай ID позиции и `projectId`; для `survey-plan` — ID плана и `projectId`. Для `counterparty-reconciliation` — ID контрагента; при необходимости ограничь выборку `projectId`. Период баланса и сверки задаётся `from`/`to` в формате `YYYY-MM-DD`. Цена заказчика — по умолчанию; внутренние цены/операции доступны только с соответствующими финансовыми scopes. Акт сохраняет свою сторону: view не превращает акт исполнителя в акт заказчика.

Для проверки вложений отчёта использовать `list_report_files`: get_report сам по себе не доказывает наличие файлов. Результат скачивания — embedded MCP resource и metadata с checksum. Сохранить точные байты средствами клиента и передать артефакт пользователю. Не печатать base64, не выдавать remcod://artifacts/... за HTTP-ссылку. Клиент без скачивания ресурсов должен открыть документ в приложении; файлы больше лимита скачиваются в REMCOD.

Экспорт не подписывает акт и не меняет смету. Себестоимость не включать в клиентский документ. Организационная `finance_report` остаётся JSON-сводкой, а не PDF-балансом. Этот инструмент не строит PDF-прайс-лист, не экспортирует страницу Knowledge, отдельные тикеты/пины чертежей, platform billing, публичную смету конфигуратора, печатные листы чертежей или moodboard/canvas. Если файл уже сохранён в `ProjectDocument`, используй `download_project_file`; не выдавай его за live-экспорт другого типа. Не маскируй неподдерживаемый тип документом другого вида.
