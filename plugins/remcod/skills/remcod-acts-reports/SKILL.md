# Отчёты и акты

## Как устроен учёт

Отчёт, акт, платёж и распределение оплаты — связанные сущности, которые нельзя складывать как четыре начисления. Признание работ и начислений брать из серверного контракта; submitted или draft не означают принятые работы. Счёт заказчику сам по себе не подтверждает поступление денег.

Если discovery содержит `get_project_balance_report`, брать formula и summary из сервера. Текущий reader считает подтверждённые клиентские поступления минус принятые строки отчётов по ценам заказчика; импортированные отчёты без пакета оцениваются по их принятым клиентским актам. Сами по себе акты не добавляют второе начисление. Если ключ скрыт, использовать доступный get_project_finance_context и явно назвать его серверный показатель; не выдавать другую формулу за ту же ведомость. При summary.complete=false полный баланс неизвестен; показать knownBalance с предупреждением. Итоги всего проекта не суммировать по страницам.

## Чтение

- `list_acts` — акты проекта и их статусы.
- Отчёты и их строки — через доступные инструменты каталога; при отсутствии прямого инструмента использовать `search_capabilities` в режиме чтения.
- Финансовый контекст проекта — `get_project_finance_context`.

## Изменения

Перед изменением пройти `remcod-write-preflight`.

- Новый акт по принятым работам: `create_act` — черновик.
- Смена статуса акта (отправка, подписание, отклонение): `update_act_status` — решение, после которого документ меняет юридическое состояние; применять только после явного согласия.

## Ответ

Цены исполнителя и заказчика не смешивать: заказчику показывать только его цены. Суммы брать из ответа сервера. Непринятые отчёты не считать выполненными работами.

## Отчёт с файлами и оплатой

Прочитать `get_report_sources`, выбрать реальные executionItemId, статьи и контрагента. Для ручной строки нужны название, единица, объём, цена заказчику и себестоимость; для распознанной — fromReceipt и сверка неоднозначных чисел. Файлы загрузить по `remcod-files-exports`; attachments — до 20 уникальных ID документов выбранного проекта.

`create_work_report` готовит works/procurement и необязательный payment в одном черновике. Показать серверные итоги, счёт, сумму, дату, режим plan/record. Не выбирать record только из-за текста «создай платёж»: план и запись состоявшейся оплаты различаются. Применение сохраняет отчёт и оплату атомарно; перечитать связь оплаты, не создавать отдельный дублирующий расход.

Отклонённый отчёт может сохранять историческую оплату. Факт оплаты не делает отчёт принятым; отклонение не даёт права автоматически удалить или отменить деньги. Показать расхождение и предложить сверку. Файлы отчёта, файлы его строк и подтверждение оплаты — отдельные связи; проверить каждую запрошенную связь после записи.

## Акты за период

Период превратить в конкретные даты с timezone проекта; использовать фильтры текущей схемы `list_reports` и пройти cursor-страницы. Прочитать строки отчётов и существующие акты: исключить уже актированные, отменённые, отклонённые и непринятые объёмы. Разные проекты, контрагенты, стороны и валюты — отдельные акты. ID пакета отчёта не является workReportId строки.

Если сервер запрещает акт по пакетному отчёту, не обходить это ручными строками: использовать существующий акт/lifecycle. Показать источники и пропуски, подготовить `create_act` в draft/sent, после подтверждения перечитать акт и выгрузить PDF. Экспорт не означает подписание.
